## Graph-partitioning baseline

The QIG preprocessor supports both the proposed greedy edge contraction (`EC`)
and a capacity-aware recursive Kernighan--Lin graph partitioner (`KL`). Both
produce the same superqubit representation consumed by the existing TACO
solvers. The dedicated runner uses the exact cluster settings from Tables II,
IV, and V and generates table-ready CSV, Markdown, and LaTeX files:

```bash
python -m src.scripts.partition_comparison --table IV
python -m src.scripts.partition_comparison --table V
```

Runs are checkpointed in `result/partition_comparison/summary.json` and resume
automatically. By default the runner executes both EC and KL with TACO-L and
TACO-L+PA. Use `--methods EC` or `--methods KL` for a subset. Legacy EC results
in `result/efficiency` are used only as a fallback until controlled EC results
have been generated by this runner.

Each method receives a total budget of 600 seconds by default. The measured
EC/KL preprocessing time is subtracted before setting the Gurobi time limit, so
every table entry uses at most ten minutes in total. Override the budget with
`--total-time-limit SECONDS` if needed.

To refresh only the EC/KL preprocessing times on the same machine without
rerunning Gurobi or deleting solver checkpoints, use:

```bash
python -m src.scripts.partition_comparison --table all --preprocess-only
```
